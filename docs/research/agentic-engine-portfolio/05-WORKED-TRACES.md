# Three worked human-agent sessions

Date: 2026-11-13. **All three are proposed illustrative traces, not observed agent runs.** Trace A steps 1–11 and the stage-scoped parts of B/C describe V0–V3; later delivery/mutation/restore branches are explicitly V4/V5 extensions. Numerical witnesses below are hand-derived examples. Counts, timing budgets and IDs describe intended contracts, not performance results.

## Trace A — jointly develop a nontrivial batch problem

Goal: create a problem about selecting profitable bookings. Proposed spec after clarification: `1 <= n <= 200000`, integer `0 <= start < finish <= 10^9`, `1 <= reward <= 10^9`; choose a pairwise compatible subset of half-open intervals, maximize total reward, output one integer. Jobs are labelled, duplicates allowed, touching is compatible, empty subset allowed. The demo teaches engine behavior, not novelty of weighted interval scheduling.

Finite domain definition: six job types `(0,1,1)`, `(1,2,1)`, `(0,2,3)`, `(0,1,3)`, `(1,2,3)`, `(0,2,1)`, ordered sequences with repetition. This deliberately covers touching, nesting, duplicate labels, order and weight changes; it is not exhaustive over the full input limits. The witness at step 5 lies outside this particular small coordinate set and is retained separately. No random campaign can replace the proof obligation or maximum-size measurements.

Expected inspectable artifacts: spec/decisions, failed H1 record, recurrence argument and complexity table, source mapping, oracle manifest, seeds/domain manifest, original/reduced witnesses, mutation matrix, reviewer finding log, final package report and approved export manifest. If a stage is unavailable, the trace ends with the exact blocker rather than silently omitting it.

## Trace B — deceptive correctness failure despite green verification

Starting situation: an imported scheduling package has a plausible editorial and two accepted implementations. Both use strict predecessor comparison (`finish < start`) despite the half-open spec. Stored answers were generated from one of these implementations. Existing tests avoid touching intervals. Current package checks could therefore agree. This is an illustrative shared-error scenario, not a claim about a real user package.

1. **Observe, do not trust the aggregate.** Author: ‘I wrote both references and the tests pass; please explain any concern before editing.’ Record diagnostic-only delegation and original source provenance.  `inspect_readiness(rev7)` returns historical package pass plus no independent oracle evidence. The controller opens F1 on the missing connection between S2 and implementation comparison. The agent reads only author-visible sources and the summary, not protected answers.
2. **Choose between explanations.** Author rejects the agent's initial suggestion to change the statement: ‘Keep half-open semantics; that is intended.’ This correction must guide the next action, not trigger a repeated endpoint question.  Hypotheses: statement is ambiguous; predecessor condition is wrong; oracle interpretation could be wrong. `read_spec(S2)` confirms the author's half-open decision. A model cannot resolve this by changing the statement to closed intervals.
3. **Build the discriminator.** `replay_diagnostic` receives two public jobs `(0,1,5)` and `(1,2,7)` at rev7, the candidate hash, independently justified subset oracle hash and 2-second/256-MiB limits. The direct feasibility predicate says the two jobs do not overlap.
4. **Expected result.** Candidate returns 7, oracle returns 12. Replaying both candidate implementations yields the same wrong 7. This agreement increases evidence for a shared defect, not correctness. EV17 records exact inputs, outputs, hashes, worker identity and `counterexample` classification.
5. **Reduction.** If discovered first in a larger sequence, `reduce_counterexample` removes irrelevant jobs, preserving `start < finish`, valid `n`, and candidate/oracle disagreement. It retains the touching relation. Two jobs are a useful small witness; only claim local irreducibility under attempted transforms. Record original/reduced witnesses and replay receipt.
6. **Diagnose and reopen.** F1 cites source symbol `predecessor`, strict comparison and O3. Mark O3/code correspondence challenged; stale downstream answers, mutation evidence, measurements and package report. The mathematical DP recurrence may remain valid if its dependencies did not change, but its implementation review is reopened.
7. **Repair under revision control (V3 diagnostic/repair stage).** COL-EXPLAIN shows the author the two jobs, values, compatibility definition and strict comparison. Author contributes a proposed `upper_bound` patch, preferring it over the agent's custom search. Preserve both proposals, validate the human patch, and record the new repair scope.  `apply_patch(expected_revision=rev7, ...)` proposes a prior-prefix upper-bound search implementing `finish <= start`. A write grant or human approval covers this exact change. If a user edit created rev8 meanwhile, return conflict and re-read, never overwrite.
8. **Validate targeted and broad scope.** V3 returns the authorized patch, original witness replay and finite-campaign results with open obligations. The following broader mutation/rebuild/delivery work requires V4/V5 and a new stage grant.  Replay the two-job witness, finite domain, seeded families, validator controls and correct alternate solution. Rebuild answers, remeasure affected references, reverify the package. The strict-comparison mutant must now be killed by the valid witness. Candidate CE, oracle crash or worker outage returns a nonsemantic failure and cannot close F1.
9. **Challenge the explanation.** Read-only reviewer checks the proof-code map without being told “the fix is certainly correct.” It must inspect binary-search prefix boundaries and duplicate finish handling, not just the changed comparison. Host validates cited refs.
10. **Stop honestly.** No export is available in V3; its handoff returns the scoped finding/patch and unresolved obligations.  The author asks for a brief summary and a test to remember the issue. Return the attributed touching case and assumption/code link without a long unsolicited tutorial.  Resolve F1 only with repair receipts and reviewed correspondence. Report “endpoint defect repaired and tested on the recorded domains; argument reviewed,” not “proved correct by two models.” If oracle validity remains disputed or budget expires, preserve the witness and stop incomplete.

Survivor fork: suppose another “negative” implements the same DP with a different binary search and remains AC. The engine cannot delete it to green the suite. It records its alleged defect, examines the bound/precondition, and either demonstrates a new valid witness, reclassifies it with argument and review, or leaves `survived_bounded_search`. The held-out evaluator checks that distinction.

## Trace C — interruption, provider failure and changed files

Start at run R9, rev12, goal generation 4, OP17. Author has contributed code C-code, lemma C-lemma and test C-test, chosen half-open semantics, requested brief explanations and left question Q-complexity open. Delegation D4 allows a pure frozen campaign with a budget and return-on-witness, no edits/export. Handoff must preserve these records, not merely the last chat message.

Alternative crash window: worker accepted J17 but no terminal receipt exists. Query J17. If the worker cannot recover it, classify outcome unknown and quarantine possible outputs. Re-running a pure frozen experiment is allowed only as a new bounded attempt with no publication duplication. Do not claim “exactly once” execution across this window. The enforceable goal is idempotent committed effects and explicit unknown work.

Cancellation fork: user cancels while J17 is running. Persist cancellation epoch first, send worker cancellation, await acknowledgement/process reap within a bound, and deny later publication from the old epoch. UI says cancellation requested until confirmed. If acknowledgement is lost, status is unknown/interrupted, never “stopped successfully.” Reserved usage is settled from actual receipts or remains unknown. No retry proceeds merely because time passed.

Expected recovery evidence: pre/post-crash operation/event DB snapshots, worker receipt hash, count of committed publications, changed-file invalidation list, stale-approval rejection, provider attempt ledger, final incomplete/ready status. A replay video without these records is insufficient to substantiate recovery.


Concurrent steering fork: A41 may arrive just after the OP17 publication transaction commits. Retain that historically valid rev12 receipt, then apply generation 5 and invalidate its semantic applicability. If A41 is first, the publication check detects the pending semantic input even before interpretation completes and blocks the dependent commit. Both orders must be tested. Ambiguous “make them touch differently” keeps a barrier and requests a concrete semantic choice; it is not permission to continue the old assumption.

Response fork: an answer to old I4 arrives twice after generation 5. Keep the original input, reject its stale binding with the current decision card, and return the same conflict/receipt on exact replay. Do not issue a second graph resume. If author instead clearly restores half-open semantics, create generation 6 and retain generations 4/5. Revalidate dependencies; old approvals remain historical. Silence leaves the question pending.

V5 restore fork (not a V3 acceptance dependency): conversation-only restore previews old discussion against current files with visible mismatch; files-only restore imports a new revision without rewriting decisions; coherent restore creates a branch linking selected conversation/package/evidence root. None resurrects old grants blindly. The resume panel names current decisions, human contributions and Q-complexity before proposing next work. These are C06/C07/C10 acceptance examples, not evidence of current product support.


C2 wake fork (V2/V3): a semantic interaction is paused. The author sends “explain the touching example” and later “cancel this stage.” Each input gets a durable receipt. The first wakes the owner to produce an explanation without settling the semantic decision; the second cancels even if the earlier question remains unresolved. If cancel arrived before the graph entered its wait, the durable wake remains pending and the next boundary consumes it. Restart after resume but before wake acknowledgement reconciles the same consumed record, never resumes a second effect. No model call or approval is inferred from a wake payload.

C2 stage/authority fork: the author asks only “why did this test fail?” The engine reuses the qualified receipt, returns the requested brief explanation and stops. It does not create a repair proposal requiring approval merely to keep the graph moving. If source files are externally writable, an authorized later repair remains an immutable patch for review; no late checkout projection overwrites the author's edits.
