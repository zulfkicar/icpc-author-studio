## 1. LangGraph capabilities: responsibility, choice and test

Installed compatibility evidence: LangGraph **1.2.20**, LangChain **1.4.9**, SQLite saver **3.1.3**. Probe code and results inspect signatures and run seven isolated, no-model experiments. G1–G7 are framework observations, not passing product acceptance tests. C01–C12 below remain proposed. All application integration, concurrency and worker guarantees are unvalidated until implementation.

| Capability and decision | Concrete responsibility / adoption reason | Compatibility and behavioral test |
|---|---|---|
| Typed state/input/output/context schemas — **adopt V1–V3** | Parent RunState carries IDs; scoped child types prevent contribution text becoming capability or hidden state. Runtime validation at persistence/API/effect boundaries, not just TypedDict. | StateGraph schema parameters inspected; G1 exercises an embedded child with shared schema; narrow projection/privacy enforcement remains an integration test. C04 rejects a malformed contribution and preserves original; C07 rejects wrong response kind. |
| Reducers — **adopt narrowly V2** | Merge immutable evidence references by ID; parallel result aggregation waits for V4; single-writer parent owns spec, generation, budget and pending decisions. Never additive-append competing semantic truth. | G5 demonstrates additive fan-in only. Future reducer tests: associative/commutative/idempotent ID union, conflicting same-ID payload rejected, shuffled duplicate events produce identical state. C06/C10 assert no lost correction or double charge. |
| Conditional edges — **adopt V3** | admit_action routes a validated choice by evidence/scope, assess returns to framing on semantic conflict. Two meaningful same-goal routes in 03. | G1 route branches pass; test invalid route cannot dispatch a tool, ambiguous semantics goes to human, reviewed code takes targeted test path. C01/C02. |
| Command — **adopt V2–V3** | Validated update/goto for control, resume only after interaction service validates response ID/revision/generation/hash. No static edge plus goto double successor. | Signature and G2 resume pass. C07 duplicate resume has one receipt, stale response cannot mutate. Graph structure test catches double routing. |
| Dynamic interrupts — **adopt V2** | One host Wake envelope serves await_human/await_operation and future approve_export. Single owner/outbox handles response, steering, cancellation and worker races without concurrent graph invocation. Human wait needs no model polling. | G2 close/reopen resume passes. C07 silent pending decision blocks dependent work; C08 cannot forge worker wake as approval; CR02/CR03 cover arrival-before-pause and unresolved input cancellation. Node-before-interrupt replay is explicit in 03. |
| Checkpoints/durability — **adopt V2** | Save parent progress synchronously at boundaries; application journal still owns effects. Reconcile checkpoint with durable inbox/receipts on restart. | G2 uses SQLite and sync durability. C10 failpoints before/after receipt/checkpoint prove one committed effect. DB/file durability on supported platforms still needs qualification. |
| Thread identity/namespaces — **adopt V1–V2** | Stable run/thread identity per branch; workspace/run ownership checked by API. Child namespaces isolate local context. New branch never silently replaces old thread. | G1/G2 cover basic configured thread/child behavior, not namespace privacy guarantees. C10 isolation test two threads and stale branch input; check workspace identity on every request. |
| Memory / Store — **defer persistent Store V6; reject transcript-as-truth** | Per-problem claims/contributions live in application DB. Optional explicit saved explanation preferences can later use Store namespace `(user, preferences)` with opt-in/edit/delete. No cross-problem proof truth or private code memory. | G7 InMemoryStore works but is not durable. V6 test namespace isolation/deletion and absence of automatic preference inference. C11 per-run preferences work without Store. |
| Scoped subgraphs — **adopt V3** | Collaboration/investigation/editing/review have narrow schemas, capability projections and inherited checkpoints. Same model by default; no automatic additional agent. | G1 compiles and executes scoped child. C04 reviewer cannot see excluded conversation, cannot publish edits; C09 approval binds stored patch returned through parent. |
| Streaming — **adopt V1–V3 basic updates; defer richer modes** | Framework updates support diagnostics; application durable events deliver meaningful progress/input status. Token text optional. Reconnect by application seq, not ephemeral stream. | G7 updates tested. C06/C10 browser reconnect dedups events and shows received vs applied. Newer event-stream examples, task/debug/checkpoint stream forms require separate pinned adapter tests before adoption. |
| Bounded Send fan-out/fan-in — **defer production V4** | Useful for independent deterministic campaign shards; no concurrent shared edits or votes on proof. First slice one campaign, serial model decisions. Aggregate only complete typed receipts under shared reservation. | G5 two branches/reducer pass. Future test one failed shard yields incomplete, duplicate shard counted once, max concurrency and cancellation enforced. C05 campaign claims only completed scope. |
| RetryPolicy — **adopt selective V2** | Pure reads/transient model transport can retry under shared attempt ceiling. Publication uses journal reconciliation, never generic replay-on-exception. | G4 explicit ValueError predicate/max2 attempts pass. CR05 combines transport and schema failures under ONE three-attempt ceiling. No nested SDK/graph retry policies. C10. |
| Timeout/error_handler — **adopt after contract tests V2–V3** | Bound node work; classify exhausted retry as resumable/incomplete, not success. Independent worker deadline and cancellation still required. | Signatures available, dynamic behavior NOT tested. V2 test timeout before/after dispatch, handler cannot suppress cancellation or unknown outcome, late worker publication denied. C06/C10. |
| Recovery — **adopt V2** | Reconcile application receipt and pending input before graph resumes; old result may be historical while current generation invalidates applicability. | G2 demonstrates checkpoint persistence only. C10 injects every publication crash window; 03 defines unknown outcome. Framework replay does not establish exactly-once physical execution. |
| History / branching — **adopt read-only history/current resume V2; defer restore mutations V5** | Inspect history and resume current session in V2; V5 creates branches tied to revision/evidence root with conversation/files/coherent restore. Never reuse old grants without current checks. | G3 update_state leaves historical snapshot intact; no file rollback tested. CR10 rejects restore mutations in V3; C10 tests all three restore types before V5 enablement, and stale approval cannot revive. |
| CachePolicy/cache — **defer general cache V4; reject effect/approval cache** | Cache pure parsing/derived diagnostics only with source/spec/toolchain/resource/profile/visibility hashes. Do not cache human decisions, readiness, provider side effects or writes. | G6 same-input hit/changed-input miss. Future cache key test changed semantics/toolchain/visibility misses; stale result cannot authorize an effect. C06/C09. |
| Tracing — **adopt local events V1; defer hosted tracing** | Local trace IDs tie model proposals, inputs, operations, receipts and explanations to run/revision without private reasoning. Redact before storage; optional external trace export only with explicit scope. | trace_policy signature exists, backend not exercised. C10 local trace reconstructs sequence, synthetic secret never emitted; no remote telemetry in research. |
| Test/replay seams — **adopt V0** | Fake model adapter, simulated worker, clock/input scheduler, reducer tests and DB failpoints. Replay saved outcomes separately from new inference. | G1–G7 illustrate framework-only seams. C01–C12 scripted fixtures plus independent-author study in 06 establish behavior later. |

## 3. Revision C1 record and preserved evidence

Before revising, archived the exact 17-file package (including the original 08 amendment) to pre-revision-package.zip. baseline.json records package and tracked-source hashes. The initial source inventory, initial diagnosis, original seven probes and original validation outputs are historical and unchanged. New G1–G7 results are stored separately; no original claim has been relabelled as a new product test.

Changes: 01 adds current collaboration seams/gap; 02 revises framework rationale and compatibility evidence; 03 replaces the underspecified loop with node/subgraph/state/interaction/publication contracts; 04 integrates joint procedures and base prompt; 05 replaces solitary examples with joint sessions and failure paths; 06 adds scripted authors, independent authors and equal-tools collaboration ablation; 07 moves collaboration and usable presentation into V0–V3 and reconciles all 56 old tasks; README now describes one coherent design. This document replaces the separate amendment with the capability and requirement map.

Scope decisions: one local author, one narrow exact-integer batch family, serial model control, SQLite, local events, bounded code execution through a qualified worker. Defer shared multi-author editing, automatic cross-problem memory, parallel model agents, broad checkers and rich branch visualization. User collaboration is not deferred. Production source, previous plans and unrelated uncommitted files are preserved.

Open implementation decisions to settle with offline V0/V1 evidence: synchronous SQLite lock/WAL behavior on supported Windows/WSL paths; minimal schema migration/version compatibility; local session actor identity and browser reconnect details; provider cancellation/usage reconciliation; calibration of interaction/retrieval/time caps. These do not block the design. No API/subscription entitlement or provider conformance claim follows from the framework probes. See new validation for exact limits.


## 4. C2 critical review: resolved design defects

Critical review record records the before/after findings and remaining limits. Main documents were reconciled, not overridden by this section. The exact C1 package (27 files) is preserved in pre-review-package.zip. C1 and original evidence files were not rewritten. C2 validation records new document/preservation checks only; G1–G7 were not rerun or promoted to product tests.

| Correction / acceptance subcase | Owning design and procedure | Implementation gate |
|---|---|---|
| CR01 single route + saved continuation | 03 routing/Continuation; all methods reuse admitted work | V2 durable continuation, V3 routes |
| CR02 wake races + single owner | 03 owner/outbox/host Wake; COL-HANDOFF | V2 |
| CR03 input deadlock/response lifecycle | 03 ordered disposition/one inbox; COL-FRAME/HANDOFF | V1 schema, V2 wake, V3 explanation |
| CR04 stale explanations and evidence | 03 conservative ingress barrier/raw receipts; COL-EXPLAIN/REPAIR | V2 fence, V3 UI |
| CR05 bounded retries/reservations | 03 shared attempts/deadlines; base workflow | V2 ledger, V3 adapter |
| CR06 file projection/runtime ownership | 03 immutable publication/managed checkout; COL-REPAIR | V2 |
| CR07 stage boundary/no forced ceremonies | 03 StageReturn vs DeliveryReady; 04 stage-scoped procedures | V3 |
| CR08 invalid mutant/empty input distinction | 04 positive-reward domain; COL-COMPARE/TEST | V0 grader fixtures, V3 judgments |
| CR09 actor/blob/schema boundary | 03 UI/API + canonical records; COL-TEST/REPAIR | V1–V2 |
| CR10 first-slice vs delivery/restore | 03 gates, 05 labelled future forks, 07 exit matrix; COL-HANDOFF | V3 rejection, V5 enablement |

Overengineering removed from V0–V3: full export readiness, restore mutations, a general scheduler, parallel result reduction, cache, external AgentDriver implementation and a mandatory sequence of all collaboration procedures. Keep four logical subgraphs because they separate context/capability and durable waits, but implement small deterministic steps as ordinary functions. Keep two databases because checkpoint internals and domain receipts have different owners; do not add a third event store. These decisions preserve useful collaboration while making its first exit testable.
