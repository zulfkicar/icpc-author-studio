# A collaborative, evidence-directed ICPC authoring engine

Research date: **2026-11-13, Asia/Karachi**. Status: completed research and proposed design, **not implemented or live-qualified**.

**Recommendation:** retain LangChain/LangGraph, and build an explicit revision-aware graph for joint framing, investigation, editing and review. Build one complete weighted-interval-scheduling investigation first: jointly specify semantics, fairly test the author's preferred approach, reject a plausible greedy rule, derive and challenge a DP, obtain an independently justified small oracle, preserve a counterexample, repair code, invalidate stale evidence, resume interrupted work, accept steering without stale publication, and return a reviewable stage result. Full package readiness, approval and export follow in V5.

The portfolio contribution is the engineering of that investigation: the model chooses useful hypotheses and experiments, while code controls authority, provenance, recovery and completion. More role names, graph nodes, or longer prompts would not establish this capability.

## Decision and scope

First showcase supports local single-author batch problems with exact integer output, C++20 candidate solutions, a separately derived bounded oracle, and a reviewable diagnostic/proof/patch handoff. One explicit ICPC export profile is a V5 delivery goal, disabled in V3. The weighted scheduling example exercises both a failed greedy hypothesis and a correct DP, so it provides more depth than a sum demo without requiring many domain packs. Add a graph family only after this slice works on held-out variants.

Retain the editor, framework tools, SQLite checkpointing, interrupts, deterministic package checks and worker separation. Repair execution and evidence integrity before trusting new autonomous experiments. Keep interactive judging and general custom checkers outside the first showcase capability profile. Existing packages stay readable with explicit legacy/unsupported labels. Do not erase their historical evidence.

No new production modules, dependency installation, services, deployment, private credential reads, live provider calls, generated submission execution or paid evaluation were part of this assignment. Added Python files are research inspection/validation utilities only. Existing modified and untracked documents were preserved.

## What the research establishes

The engine already exercises model-directed tool selection and adaptation. Its agency is shallow mainly in **domain method, collaborative reasoning and enforceable evidence semantics**, not because `create_agent` is inherently shallow. Seven synthetic probes confirm specific current gaps. No claim is made that the proposed architecture improves success rates until the independent comparison is run.

After implementation and qualification, a defensible claim would be: “A local problem-setting partner that incorporates author contributions and conducts bounded, reproducible correctness investigations and keeps claims, tests, reviews and approvals tied to exact revisions.” Claims of autonomous contest readiness, general mathematical correctness, independent model consensus, universal subscription support, or formal verification of generated C++ remain unjustified.
